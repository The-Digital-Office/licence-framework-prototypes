Licence Allocation Prototype

The baseline is produced by the baseline tool and pasted in here. This tool runs the two F3 gates, checks special group membership, applies the right baseline, lists any specialist capabilities this person needs on top, and records the decision.

Prototype for comment (v1.5). P6 (additional requirements) is now a structured list of specialist capabilities named in plain language, so the decision record tells HR and IT exactly what to provision.

Pre-computed baseline

Paste the baseline tool's output. The org-wide baseline is the licence stack that applies to everyone. Special group baselines apply only to people in that group, usually stacked on top of or replacing the org-wide baseline.

Where this comes from. The baseline tool translates the council's requirements into licence stacks. That translation happens once at council level; this allocation tool applies the result to each person without re-translating.

Scenario details

Device licensing is a scenario-level decision. Run once for the whole shared-device population, not per user. The baseline you pasted at the top still applies to every user in this scenario.

D1Procurement
Before anything else

Test 1: agreement eligibility

Can the council procure a device licence under its current Microsoft agreement?

ConstraintIf the SKU is not available under the agreement, the rest of the flow is academic. Confirm this test first.
D2IT
Per scenario

Test 2: technical fit

Do the users of this shared device need only what a device licence covers, plus their existing user licences for anything else?

NoteMicrosoft 365 Apps for Enterprise (Device) covers desktop productivity apps for a shared device. Intune device-only manages the device but does not cover user features like email. These often stack rather than compete.
T1Users' application needs are covered by the device licence
T2User features needed (email, calendar) are covered by existing user licences
T3No line of business systems require named-user context to function
T4No individual users have compliance obligations that device licensing cannot satisfy

Actual council pricing

Test 3: commercial fit

Does device licensing cost less than per-user upgrade at this user-to-device ratio?

ConstraintAt small ratios (two users per device) device licensing rarely wins. At larger ratios (ten users per device) it usually does.

Any other reasons device licensing would not work?

C1The device supports the enrolment path required for the licence

C3No per-user audit or attribution requirement exceeds what device licensing supports
